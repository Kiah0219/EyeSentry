# 003 · `/api/settings` 校验顺序导致部分生效

- 严重度：P1
- 状态：未修复
- 范围：`web.py`
- 发现：2026-10-25 项目审计

## 现象

请求体 `{"classes": [0], "conf": "bad"}` 返回 400，但白名单已经被改成 `[0]`。客户端看到的是「整单失败」，服务端实际改了一半。

## 位置

[web.py:219](../../web.py#L219)：先校验并应用 `classes`，再校验 `conf`；`detect` 与 `channel` 的校验在更前面。

## 根因

校验与落状态交错执行，没有「全部校验通过后再统一应用」的阶段。PRD 7.4 写的是非法取值「本次请求的任何设置都不生效」。

## 建议修复

先在局部变量里校验并规范化所有字段（`classes`、`conf`、`detect`、`channel`），任一项失败直接 400；全部通过后再逐项写入。可以顺手把 `set_classes` / `set_conf` / `set_enabled` 合并成一次带锁的更新，避免中途被推理读到半套配置。

## 验收

- `{"classes":[0],"conf":"bad"}` → 400，且 `/api/status` 里的白名单不变。
- 合法多字段请求 → 全部生效。
