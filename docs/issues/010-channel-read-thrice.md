# 010 · 一次事件内三次读取 `self.channel`

- 严重度：P2
- 状态：未修复
- 范围：`runtime.py`
- 发现：2026-10-25 项目审计

## 现象

处理一条停留事件时，代码在三个位置分别读 `self.channel`：决定是否合成、决定是否本体播放、决定 `play_web`。如果用户恰好在处理过程中切换通道，可能出现「按 web 合成了音频，但 `play_web=false`」或「按 device 播放，同时告诉页面也播」的不一致。

窗口很小，但修复成本几乎为零。

## 位置

[runtime.py:120](../../runtime.py#L120)、[runtime.py:124](../../runtime.py#L124)、[runtime.py:136](../../runtime.py#L136)

## 建议修复

在 `_handle_event()` 开头 `channel = self.channel`，后续只用局部变量；合成、播放、广播都以同一次快照为准。

## 验收

- 代码审查确认事件内只读一次通道。
- 事件处理过程中反复切换通道，不出现两路同时出声或该出声却静音。
