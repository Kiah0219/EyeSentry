# 一期用 MJPEG 推流，WebRTC 留到二期

浏览器端画面先用 MJPEG（`multipart/x-mixed-replace`）传输：后端每帧编码成 JPEG 直接写出，前端一个 `<img>` 标签即可显示，无需信令服务器、无需 ICE、无需处理编解码协商。代价是带宽偏高（720p/15fps 约 2~4 Mbps）且延迟虽在 1 秒内但不如 WebRTC。决定把推流输出收敛成一个独立函数（输入帧、输出字节），二期改 WebRTC 时只替换该函数与前端播放器，不动检测与事件逻辑。

## Consequences

- 无线网络较弱时需要降低分辨率或帧率。
- 前端必须保留「切换到 WebRTC」时不影响其他模块的边界，这是二期能低成本升级的前提。
